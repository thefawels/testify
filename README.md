# Testify

Минималистичное PWA для тестов из CSV. Без сборки, npm и сервера: HTML, CSS и JavaScript.

![Иконка Testify](docs/icon-192.png)

## Что умеет

- Импорт CSV с названием и эмодзи теста.
- Случайный порядок вопросов и ответов при каждом прохождении.
- Пояснение к выбранному ответу, таймер и повторение ошибок.
- Общая статистика, календарь активности, динамика и история по тестам.
- Удаление тестов и отдельный сброс статистики.
- Установка на главный экран и офлайн-работа после первого успешного открытия.

## Опубликовать на GitHub Pages

1. Распакуй ZIP. Внутри папки `testify` находятся `docs`, `assets`, `scripts` и этот README.
2. На GitHub создай новый репозиторий, например `testify`. Для бесплатного GitHub Pages выбирай **Public**.
3. Через **Add file → Upload files** загрузи **содержимое** папки `testify`, а не сам ZIP и не дополнительную внешнюю папку. Сохрани изменения в `main`.
4. В корне репозитория должны быть папки `docs`, `assets` и `scripts`. Главная страница должна лежать по пути `docs/index.html`.
5. Открой **Settings → Pages → Build and deployment**.
6. Выбери **Deploy from a branch**, ветку **main**, папку **/docs**, нажми **Save**.
7. После завершения публикации GitHub покажет ссылку вида `https://USERNAME.github.io/testify/`.
8. На iPhone открой эту ссылку в Safari → «Поделиться» → «На экран Домой».

Загрузка папок через браузер удобнее на компьютере. Скрытый `.nojekyll` полезно загрузить вместе с остальными файлами; приложение не использует файлы с подчёркиваниями, поэтому его пропуск при ручной загрузке не блокирует эту структуру.

Никакие секреты, ключи API или вход через ChatGPT не нужны. Сам сайт GitHub Pages будет общедоступен. Загруженные через интерфейс тесты остаются только в браузере пользователя и не попадают в репозиторий.

Официальная инструкция: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Запустить локально

Из корня проекта:

```bash
python3 -m http.server 8000 --directory docs
```

Открой http://localhost:8000/. На Windows команда может называться `python`. Не открывай `index.html` двойным кликом: JavaScript-модули и service worker требуют HTTP. На опубликованном сайте нужен HTTPS, localhost подходит для разработки.

## Файлы

- `docs/` — готовое приложение; именно эту папку публикует GitHub Pages.
- `docs/app.js` — интерфейс и логика тестов.
- `docs/csv.js` — чтение и проверка CSV.
- `docs/test-data.js` — работа со статистикой и перемешивание.
- `docs/analytics.js` — расчёт метрик.
- `docs/tap-guard.js` — защита от случайного выбора при прокрутке.
- `docs/style.css` — оформление, включая исправление шапки iOS.
- `docs/manifest.webmanifest` — название, запуск и иконки PWA.
- `docs/sw.js` — офлайн-кеш.
- `assets/icon-source.png` — исходник временной иконки.
- `scripts/generate-icons.py` — создание PNG нужных размеров.

## Хранение и перенос

Тесты, история и настройки сохраняются в `localStorage`, а файлы приложения — в Cache Storage. Серверная база и синхронизация между устройствами пока не подключены.

GitHub Pages — новый адрес. Данные с прежнего `testify.fawels.chatgpt.site` автоматически сюда **не переедут**: браузеры разделяют хранилища разных сайтов. На новом адресе заново загрузи исходные CSV; история останется на старом сайте. Этот архив содержит код приложения, а не тесты и результаты из твоего телефона.

Храни исходные CSV отдельно. Очистка данных сайта может удалить тесты и историю. Изменение адреса или имени репозитория также меняет область хранения этой версии.

## Формат CSV

```csv
question_id,question,answer,is_correct,comment
1,Сколько будет 2 + 2?,4,1,Два плюс два равно четырём.
1,Сколько будет 2 + 2?,5,0,Пять получится если к двум прибавить три.
```

Каждая строка — один вариант ответа. Для одного вопроса одинаковые `question_id` и `question`; от 2 до 8 вариантов; ровно один `is_correct=1`. Остальные — `0`. Кодировка UTF-8, разделитель — запятая или точка с запятой. Пример можно скачать в самом приложении. Если текст содержит разделитель, заключай поле в двойные кавычки.

## Обновления

Меняй файлы в `docs`, увеличивай `VERSION` в `docs/sw.js` (`v1` → `v2` и т. д.) и загружай изменения в `main`. GitHub Pages перепубликует сайт. Закрой и заново открой PWA после завершения публикации. Не очищай данные браузера ради обновления: это затронет твою историю.

Эта копия подготовлена для самостоятельного размещения. Служебные настройки Sites, история Git и учётные данные в ZIP не включены. Публикация на GitHub не обновляет прежний сайт автоматически.
